## Overview

- Request ID: R-20260731-0510
- Request title: Create Bulgarian investment instrument static mockup

### Background

ATISTAT needs a vivid, portable demonstration of the residential-investment analysis product described in `workdir/investment_instrument_input.md`, so stakeholders can explore the intended workflows before funding or building the production cloud application.

### Scope

The request covers a Bulgarian-language, dependency-free static website under `workdir/investment_instrument/`; an analyst-dashboard landing page with a role switcher; representative analyst, review, source-governance, reporting, guided-help, and roadmap interactions; a hybrid core financial calculator in EUR; twelve synthetic offers across eight Sofia neighborhoods; locally stored official and synthetic JSON data; an accessible schematic map; working JSON/CSV and print-report exports; an accessible full HTML representation of the source requirements; and automated checks that the unpacked folder remains self-contained and directly usable through `file://`.

### Out of scope

The iteration does not build the production cloud system, connect to live listing feeds, provide authentication or durable multi-user workflows, automate legal or financial actions, make investment recommendations without human review, modify the public ATISTAT website, or update `.aib_memory/context.md`.

Applicability: suitable as a real financing benchmark; unsuitable as a binding bank quote or a rate available to an individual buyer. Applicability: all prototype controls, dialogs, tabs, filters, comparison actions, and status indicators should use semantic HTML and remain understandable without color. Applicability: if direct double-click launch is required, runtime data should be available through a local JavaScript bootstrap or inline application data while the canonical export snapshots remain present as `.json` files and are parity-tested. Source: `https://html.spec.whatwg.org/multipage/browsers.html`.

### Edge Cases

- Opening the package through `file://` may block local JSON fetches; the direct-file-only contract requires a parity-checked JavaScript data bootstrap and an explicit smoke test without a server.
- JavaScript may be disabled or fail; navigation, requirements, help, future ideas, source notes, and core offer summaries should remain readable.
- A JSON snapshot may be missing, malformed, empty, stale, preliminary, or use a changed base year; the UI must show an intelligible data-status state rather than fabricated precision.
- Synthetic and real values may appear in the same view; each must carry an unambiguous origin/type label that is not color-only.
- Financial models may encounter zero interest, zero equity, negative cash flows, no IRR, multiple IRRs, invalid horizons, missing rent, or break-even values outside the tested range.
- Comparison may have fewer than two offers, more than the supported maximum, incompatible currencies or periods, or offers excluded by hard constraints.
- A critical due-diligence warning must override a favorable numeric score without being mistaken for a legal conclusion.
- Changing assumptions must not silently mutate a “locked” sample analysis; the mockup should either create a visible draft state or clearly label the interaction as ephemeral.
- Browser storage may be unavailable, full, or contain stale data from an older prototype version; the selected local persistence requires versioned keys, safe defaults, and a visible reset path.
- Working JSON/CSV download and print-to-PDF behavior differs across browsers and `file://` contexts; failures and fallbacks must be visible.
- Bulgarian labels, currency values, long table headings, formulas, and the complete 1,322-line requirements document must reflow on small screens without horizontal page failure.
- Keyboard focus must return after dialogs close, tab order must remain logical after filtering, and status must not be conveyed by color alone.
- The roadmap-prioritization board must not imply that a selection is saved centrally or approved when it exists only in the local browser.
- ZIP extraction may preserve a nested top-level folder; all paths must be relative and case-correct.
- The source requirements or official snapshots may change after implementation; the package must show the snapshot date and should not claim live freshness.
- The public ATISTAT site and `.aib_memory/context.md` must remain untouched even if brand assets or production concepts are referenced.

## Proposed Solution

### High-Level Concept

Build an isolated, ATISTAT-branded Bulgarian static prototype that opens directly as an analyst dashboard, uses a shared accessible multi-page shell and local persistence, and combines reviewed official context with clearly synthetic offer data. A bounded live calculator, working exports, guided help, and a roadmap board make the production concept vivid without claiming production capabilities.

- `workdir/investment_instrument/index.html`: Create the landing experience, prominent requirements link, prototype disclaimers, and primary entry into the simulated workflow.
  - Open on ranked offers, alerts, market context, and tasks for the Analyst role, with a role switcher exposing lighter Administrator and Observer/Approver states.
