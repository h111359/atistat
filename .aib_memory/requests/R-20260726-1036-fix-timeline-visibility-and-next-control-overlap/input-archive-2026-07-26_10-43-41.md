## Input

The whole section "at-home-timeline at-fade is-touched is-timeline-enhanced has-timeline-next is-responsive-enhanced is-in has-timeline-previous" is still not visible on mobile browser (tested with Samsung Note 10 Lite). Ensure the section renders properly on all screens.

The button at-tl-control--next overlaps over the section at-tl-year at-tl-year--end on some screens (not all). Ensure no overlap happens.

No additional files are needed. The clarification points are resolved.

### Goal

Ensure the Experience timeline renders visibly and remains fully usable at every viewport width from 320 CSS pixels upward. Eliminate any overlap between the desktop Next control and the ending-year block while preserving the existing timeline content, responsive behavior, accessibility, and localization.

### Users and business value

- Primary affected users are mobile visitors evaluating ATISTAT’s experience and portfolio.
- The confirmed failure affects the primary Bulgarian homepage on a Samsung Note 10 Lite in portrait orientation using Samsung Internet.
- The “ОПИТ” heading renders, but the timeline navigation and cards beneath it appear blank.
- The timeline is core portfolio evidence; its absence hides important trust and project information.
- Treat this as a high-priority presentation defect because an existing core section is unusable on a current mobile browser.

### Scope

- Diagnose and correct the blank responsive timeline beneath the visible Experience heading.
- Ensure the responsive milestone navigation and all 13 stacked timeline cards render at widths up to and including 860 CSS pixels.
- Ensure the desktop timeline renders correctly above 860 CSS pixels.
- Keep the Next control in the ending-year column while ensuring that its visible bounds never intersect the ending year or caption.
- Apply shared corrections and parity safeguards across:
  - `index.html`
  - `index-bg.html`
  - `index-en.html`
  - `index.html?lang=bg.html`
  - `index.html?lang=en.html`
  - `opit/index.html`
- Add or update deterministic regression checks for responsive visibility, layout boundaries, non-overlap, and shared-document parity.
- Verify current Samsung Internet manually and retain automated Chrome interaction coverage.

### Required behavior

- At responsive widths, the Experience heading must be followed by a visible milestone rail and the complete 13-card list.
- Timeline content must remain visible if JavaScript is unavailable, unsupported, or fails to initialize.
- JavaScript enhancement classes must not make the timeline blank, collapse its height, or render it outside the visible area.
- The page must not acquire horizontal document overflow as a result of the correction.
- The desktop Previous and Next controls must remain at least 44 by 44 CSS pixels.
- The Next control and ending-year text must have a non-intersecting visible layout at every desktop width.
- Existing keyboard navigation, accessible attributes, touch scrolling, edge indicators, active selection, gallery launchers, and focus restoration must continue to work.
- Reduced-motion behavior must remain intact.
- Bulgarian and English timeline copies must retain equivalent structure and behavior.

### Browser and viewport coverage

Support current versions of:

- Samsung Internet, including manual verification on Samsung Note 10 Lite.
- Google Chrome.
- Mozilla Firefox.
- Apple Safari.

Test representative widths around the layout extremes and breakpoint, including 320, 360, 412, 768, 860, 861, 1024, and a wider desktop viewport. Verify portrait and landscape layouts where available.

### Constraints

- Preserve the static-site architecture.
- Do not add third-party JavaScript libraries or a build pipeline.
- Preserve progressive enhancement and no-JavaScript content availability.
- Preserve all 13 milestones, project information, gallery behavior, translations, and existing destinations.
- Keep canonical and version-suffixed shared CSS and JavaScript asset copies byte-identical.
- Avoid route-specific fixes when the affected behavior belongs in a shared asset.
- Do not redesign unrelated Experience content or other homepage sections.

### Out of scope

- Changing timeline milestone content, order, imagery, or project metadata.
- Redesigning the Experience section.
- Optimizing full-resolution gallery assets.
- Changing project-detail pages or unrelated homepage components.
- Supporting obsolete browser versions outside the current browser targets.

### Assumptions

- The reported blank state is reproducible on the primary Bulgarian `index.html`; all six copies remain in scope because they share assets and duplicated timeline markup.
- “All screens” means viewport widths of 320 CSS pixels and wider.
- The defect must be absent in both portrait and landscape layouts even though the confirmed reproduction is portrait-only.
- Non-overlap means the rendered bounding rectangles of the Next control and ending-year content do not intersect and retain a visible gap.
- If physical Samsung Internet testing cannot be automated, it remains an explicit manual acceptance step.

### Success criteria

- On Samsung Note 10 Lite in portrait orientation using current Samsung Internet, `index.html` displays the milestone navigation and all 13 cards beneath the visible “ОПИТ” heading.
- At every representative width from 320 CSS pixels upward, the appropriate responsive or desktop timeline has non-zero dimensions and is visibly rendered.
- At 860 CSS pixels, the responsive rail and card list are visible and the desktop timeline is hidden.
- Above 860 CSS pixels, the desktop timeline is visible and the responsive presentation is hidden.
- The Next control’s rendered bounds do not intersect the ending-year block at any tested desktop width.
- No tested viewport produces horizontal document overflow.
- All six timeline documents preserve equivalent markup, localized labels, milestone count, and shared behavior.
- Timeline content remains visible without JavaScript.
- Existing keyboard, touch, accessibility, gallery, and reduced-motion checks continue to pass.
- Automated tests complete without first-party console errors.
- Manual checks pass in current Samsung Internet, Chrome, Firefox, and Safari.

### Potential impact

The likely change area is the shared responsive timeline and fade/reveal styling, with possible JavaScript hardening if Samsung Internet exposes an initialization edge case. Because all six pages share those assets, the behavioral correction should propagate broadly, while parity tests guard their duplicated markup.

The highest regression risks are the 860-pixel layout transition, progressive no-JavaScript visibility, timeline overflow geometry, and the desktop endpoint-control positioning. Physical Samsung Internet verification remains necessary because the current automated harness uses Chrome.
