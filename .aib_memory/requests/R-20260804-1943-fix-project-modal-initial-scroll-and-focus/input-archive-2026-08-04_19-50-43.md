## Input

On click on button "at-flagship__action" is opened a modal "at-selected-projects" for the respective project. But when the screen is small, the focus is not at the top of the modal, but it appears scrolled vertically down.  Find why is this behavior. The user wants the modal always to be loaded so the vertical scrol to be on top position.

### Goal

Diagnose, correct, and verify the project-details modal so it always opens at the top of its scrollable content, regardless of viewport size, selected project, launcher type, or previous modal scroll position.

### User Need

Visitors opening project details, especially those using short or narrow viewports, must immediately see the sticky modal header and the selected project’s facts instead of landing partway down the gallery.

### Current Behavior

When a project dialog is opened, short screens can display the modal with its content already scrolled vertically downward.

Static inspection identifies the likely cause in the shared dialog-opening handler:

- `.at-dialog__body` is the element that owns vertical scrolling.
- The handler resets `activeContainer.scrollTop`, although the active project container is not the scroll owner.
- After calling `showModal()`, the handler focuses the first focusable element inside the active project.
- For gallery projects, that element is the first enhanced gallery image below the project facts and description.
- Browser focus scrolling can therefore move `.at-dialog__body` downward to reveal that image, particularly when the viewport is short.

Confirm this causal sequence through browser interaction testing before finalizing the correction.

### Required Behavior

- Every opening of the shared project dialog must reset `.at-dialog__body` to `scrollTop === 0`.
- The sticky dialog header and the beginning of the selected project facts must be visible immediately after opening.
- The behavior must apply at every viewport size, including narrow mobile screens and short desktop windows.
- The behavior must apply to every control that opens `#selected-projects-dialog`, including:
  - Selected Projects `.at-flagship__action` buttons.
  - Desktop timeline `.at-timeline-project-launcher` buttons.
  - Responsive timeline `.at-timeline-project-launcher` buttons.
- The reset must occur on every opening, including:
  - Reopening the same project.
  - Opening a different project.
  - Reopening after scrolling within the dialog.
  - Reopening after using and closing the large-image view.
- Initial focus must move to the visible close button in the sticky dialog header without causing the dialog body to scroll.
- Closing the dialog must continue to restore focus to the launcher when that launcher remains in the document.
