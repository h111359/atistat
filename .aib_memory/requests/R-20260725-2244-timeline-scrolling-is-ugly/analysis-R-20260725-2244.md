## Overview

- Request ID: R-20260725-2244
- Request title: Timeline scrolling is ugly.

### Background

The developer reports that the homepage timeline's current scrolling experience is visually unattractive and asks for a modern bilingual UX proposal. The developer also wants the Apartment Arcadia timeline image to reproduce the Correct Project milestone's interaction state: grayscale while idle and color when hovered or selected.

### Scope

The request covers the desktop timeline's navigation, overflow affordances, selection behavior, keyboard behavior, responsive presentation, and consistent Bulgarian/English rendering. It also covers the Apartment Arcadia milestone asset and visual states, the shared CSS and JavaScript copies, regression coverage, and the corresponding product-context records.

### Out of scope

This analysis does not redesign unrelated homepage sections, change project gallery content, modify project-detail routes, replace the mobile stacked-card layout, add third-party libraries or a build pipeline, create a new Arcadia image asset, or implement any source changes during the analysis phase.

### AI interpretation

The ATISTAT homepage needs a deliberately designed continuous desktop timeline rail in place of the current bare horizontal overflow. Its desktop milestone must be fully grayscale at rest and reveal original color on hover, keyboard focus, and active selection, while the retained mobile stacked-card image remains in color. The complete contract applies to `index.html`, `index-bg.html`, `index-en.html`, `index.html?lang=bg.html`, `index.html?lang=en.html`, and `opit/index.html`, with localized controls and correct relative asset paths.

### Industry Knowledge

- The [WAI-ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) requires every item inside a tablist to be a tab, associates each tabpanel with its tab through `aria-labelledby`, wraps Left and Right Arrow movement, and optionally supports Home and End. Applicability: the current marker-and-panel relationship already behaves like automatic-activation tabs, so either the markup must be completed as a valid tabs widget or the component must adopt a different semantic pattern consistently.
- The [WAI-ARIA Carousel Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) identifies native previous and next buttons, an accessible container label, meaningful item names, and controlled focus order as appropriate mechanisms for sequential content. Applicability: explicit navigation buttons can make overflow discoverable without introducing automatic rotation; a grouped or tabbed carousel model is viable only if its semantics remain consistent with the detail panels.
- The [CSS Scroll Snap Module Level 1](https://www.w3.org/TR/css-scroll-snap-1/) defines snap positions, `scroll-padding`, and `scroll-margin` to prevent imprecise scrolling from ending at awkward partially visible positions. Applicability: proximity snapping and a defined optimal viewing region can preserve free touch/trackpad scrolling while making each milestone settle predictably.
- [WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) requires pointer targets to be at least 24 by 24 CSS pixels or sufficiently separated. Applicability: any added arrow, page, or position controls need measurable hit areas and spacing at every responsive breakpoint.
- [WCAG 2.2 Focus Not Obscured (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum) requires the focused component not to be entirely hidden by author-created content. Applicability: keyboard movement through an overflow rail must also move the viewport so the newly focused milestone and its focus outline remain visible.

- `main.js` applies tab state to anchors that are not tabs, does not maintain roving `tabindex`, does not wrap Arrow navigation, and omits Home and End behavior expected by the APG tabs model.
- `main.js` relies on native focus scrolling rather than explicitly aligning active markers; pointer selection can therefore update a panel while leaving its marker partly hidden.

### Edge Cases

- At 861 CSS pixels the interface changes abruptly from stacked cards to a thirteen-item desktop rail, producing the greatest overflow pressure immediately above the breakpoint.
- Wide tablets, touch laptops, and devices reporting no hover can receive a hover-oriented desktop design.
- Trackpads, Shift-plus-wheel input, touch panning, keyboard focus movement, and explicit arrow-button activation can each create different scroll endpoints unless they share one alignment rule.
- First and last milestones cannot be perfectly centered without intentional inline scroll padding; navigation controls must expose their disabled or wrapped state consistently.
- Multiple milestones share the year 2024 or 2025, so year-only position feedback is ambiguous.
- Company milestones currently navigate externally while project milestones select local panels; making all markers one semantic widget changes where outbound activation occurs.
- Hover-driven activation can cause repeated live-region announcements and accidental panel changes while the user is merely moving toward a control.
- Focus, hover, active selection, and pointer press can overlap; the Arcadia color-state cascade must define which state wins.
- A grayscale CSS filter cannot reconstruct color from an intrinsically monochrome or sepia source asset.
- The canonical Bulgarian page currently differs from its Bulgarian copy and from both English copies, so changing only shared CSS or JavaScript will not repair the Arcadia source inconsistency.
- Hiding the native scrollbar without adding operable, labelled controls would reduce discoverability and accessibility.
- Programmatic smooth scrolling and image transitions must become instant under `prefers-reduced-motion: reduce`.
- The page must remain usable without JavaScript: timeline content cannot become unreachable merely because enhanced navigation controls fail to initialize.
- Browser scrollbars, overlay scrollbars, zoom, text enlargement, and localized control-label length can change available rail width.
- Version-suffixed shared assets must remain byte-identical to their canonical files or the existing integrity test will fail.
- User-owned uncommitted edits already change Arcadia asset references in `index.html`; implementation must preserve the intended mobile change while resolving the desktop asset decision.
