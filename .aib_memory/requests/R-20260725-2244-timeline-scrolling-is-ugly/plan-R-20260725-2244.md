## Goal

Replace the homepage timeline's bare desktop overflow with a modern, discoverable continuous rail that emphasizes about five complete milestones and behaves consistently for pointer, touch, keyboard, and assistive-technology users. The change covers all five root homepage documents, `opit/index.html`, both shared CSS copies, both shared JavaScript copies, the browser regression fixture, the static-site test suite, and `.aib_memory/context.md`; it also gives Apartment Arcadia a full-grayscale desktop rest state and color interactive states using the existing WebP asset.

## Constraints

- Preserve the thirteen milestones, chronological order, existing initial selection, detail copy, galleries, unrelated homepage content, project-detail routes, and the stacked-card layout at and below the existing 860 CSS pixel breakpoint.
- Update `index.html`, `index-bg.html`, `index-en.html`, `index.html?lang=bg.html`, `index.html?lang=en.html`, and `opit/index.html`; localize user-facing controls in Bulgarian and English and preserve `opit/index.html` relative paths.
- Use static HTML, shared CSS, and dependency-free vanilla JavaScript; do not add a third-party library, dependency manifest, build pipeline, auto-rotation, new Arcadia asset, or unrelated redesign.
- Keep free touch and trackpad panning available above the mobile breakpoint. Hide the native horizontal scrollbar only after JavaScript confirms that labelled replacement controls and free scrolling are initialized; the unenhanced fallback must retain native scrolling and a visible native scrollbar.
- Implement one complete automatic-activation tabs model for all thirteen desktop markers. Company markers select panels, and outbound company links reside in those panels; mobile company cards use explicit native links rather than clickable `li[data-href]` proxies.
- Hover changes marker emphasis and Arcadia color only; it must not commit a detail-panel selection. Click, keyboard focus reached through tab navigation, Left/Right Arrow navigation, Home, and End may commit selection.
- Center the selected or keyboard-focused marker except where the first or last rail boundary prevents centering. Reduced-motion users receive instant movement and no new animated transition.
- Use `wp-content/uploads/2026/07/arcadia-timeline.webp` in every Arcadia desktop marker and mobile card. Apply full grayscale only to the desktop marker at rest; desktop hover, focus, and active selection and all mobile-card states remain in color.
- Preserve unrelated user-owned edits in the dirty `index.html` worktree and change only the timeline lines required by this request.
- Keep `wp-content/themes/atistat/assets/css/main.css` byte-identical to `wp-content/themes/atistat/assets/css/main.css?ver=1784544801.css`, and keep `wp-content/themes/atistat/assets/js/main.js` byte-identical to `wp-content/themes/atistat/assets/js/main.js?ver=1784544801`.
- Treat the active request as ready for one implementation iteration. If scheduling priority changes, delivery timing may change but this functional scope does not.

## Success criteria

- Each of the six timeline documents contains exactly thirteen desktop `button[role="tab"]` markers, exactly thirteen associated tabpanels, unique tab and panel identifiers, reciprocal `aria-controls` and `aria-labelledby` relationships, one `aria-selected="true"` tab with `tabindex="0"`, and twelve tabs with `tabindex="-1"`.
- Each timeline document contains localized Previous and Next buttons with accessible names and observable disabled boundary states. Directional edge fades appear only when additional milestones exist in the corresponding direction, and each control has a pointer target of at least 44 by 44 CSS pixels.
- At representative desktop viewport widths, the rail emphasizes about five complete milestones, retains horizontal overflow for all thirteen milestones, settles free or controlled movement on milestone snap positions, and keeps hover, focus, and active emphasis within each marker's visual allocation without clipping controls or obscuring adjacent targets. At and below 860 CSS pixels, the existing stacked cards remain the visible timeline layout.
- Pointer hover does not change the selected tab or visible panel. Click and keyboard focus activation select the matching panel; Left and Right Arrow keys wrap across both ends, Home selects the first marker, End selects the last marker, roving focus remains valid, and the active marker centers except at physical rail boundaries.
- Wide touch layouts support both swipe panning and visible Previous/Next controls. Without JavaScript, all milestones remain reachable through native scrolling and the native scrollbar remains visible; after successful enhancement, the replacement controls work before the native scrollbar is hidden.
- Company desktop markers are tabs rather than outbound anchors, their company panels contain the outbound links, and retained mobile company cards expose explicit keyboard-operable native links.
- Every desktop and mobile Arcadia reference in all six documents resolves to `arcadia-timeline.webp` with the correct relative path. The desktop marker computes to full grayscale at rest and color on hover, focus, and active selection; mobile Arcadia cards remain in color.
- `prefers-reduced-motion: reduce` disables smooth rail movement and all newly introduced timeline motion without disabling selection, panning, controls, focus visibility, or content access.
- The canonical and version-suffixed CSS files are byte-identical, and the canonical and version-suffixed JavaScript files are byte-identical.
- `python -m unittest discover -s tests -v` exits with status 0, all tests pass, and the browser harness reports no first-party console errors.
- `.aib_memory/context.md` records the resolved six-document timeline and Arcadia contract, accurately records the existing unittest and Chrome harness, removes the corrected accessibility issues, and retains residual synchronization and manual cross-device review risks.
