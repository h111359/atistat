## Overview

- Request ID: `R-20260731-0719`
- Request title: Static investment instrument website mockup

### Background

ATISTAT needs a vivid, portable demonstration of the proposed internal residential-investment analysis tool so stakeholders can understand the concept before a production system is designed or built. The developer requested a Bulgarian static website that opens directly from an extracted archive, represents the full product specification, uses real public reference data where responsibly accessible, and simulates the remaining product data and behavior.

### Scope

The iteration covers a new isolated prototype in `workdir/investment_instrument/`: a Bulgarian landing experience, representative offer discovery and comparison, an explainable analysis journey, source and administration views, local sample exports, a complete HTML rendering of `workdir/investment_instrument_input.md`, offline assets, direct-file browser behavior, accessibility, and focused automated checks. The prototype must clearly separate official reference indicators from synthetic property offers and must remain independent from the public ATISTAT website.

### Out of scope

The iteration excludes a production application, authentication or MFA, live external integrations, automated scraping, real individual property records, legal or financial advice, automated investment decisions, server-side behavior, a build pipeline, installation requirements, and changes to `.aib_memory/context.md`.

### AI interpretation

The requested deliverable is a self-contained Bulgarian product prototype, not a reduced copy of the public marketing website and not an implementation of the future protected cloud service. It should turn the specification into an understandable analyst journey: orient the user, expose the source and synthetic-data boundaries, show offers and comparison, demonstrate representative financial and risk calculations, preserve visible human-decision controls, provide sample exports, and offer direct access to a semantically rendered copy of the complete requirements document.

The folder must work after ZIP extraction when `index.html` is opened through `file://`, without a local server, package installation, build step, remote font, remote stylesheet, remote script, or runtime data request. Canonical JSON files remain inspection and export artifacts; browser-facing demo data therefore also needs a local JavaScript representation because direct-file fetching is not reliably portable. Every official record needs publisher, source URL, observation date, retrieval date, unit, scope, transformation, reuse status, and limitation metadata. Every unavailable offer-level fact must be synthetic, visibly labeled in the interface and machine-labeled in JSON, and must never be presented as a real listing, transaction, appraisal, or recommendation.

The full specification is too broad to implement in a static demonstrator, so completeness means representative coverage of its product concepts and traceability, not functional parity with the future MVP. The existing focused test file is useful acceptance evidence, but its prior-request coupling and several hard-coded product choices must be reconciled with the current request and the developer's answers.

### Industry and External Research

- W3C WCAG 2.2 requires keyboard operability, visible and unobscured focus, non-color status communication, programmatically determinable status messages, labels, and predictable operation. Applicability: the prototype should use native controls, visible `:focus-visible` styling, text or symbols in addition to color, `aria-live` for recalculation feedback, meaningful headings, and reduced-motion handling. Source: `https://www.w3.org/TR/WCAG22/`.
- The WAI-ARIA Authoring Practices modal-dialog pattern requires focus to move inside a modal, remain within its tab sequence, close with Escape, and return to the invoker. Applicability: any onboarding or explanatory modal should use native `<dialog>` where possible and preserve focus behavior; tabs or composite controls need their documented arrow-key patterns. Source: `https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/`.
- The HTML Living Standard permits `localStorage` access to fail with a `SecurityError` for unsuitable or opaque origins. Applicability: a direct-file prototype cannot assume persistent storage; it needs guarded storage access, an in-memory fallback, and an explicit reset action. Source: `https://html.spec.whatwg.org/multipage/webstorage.html`.
- W3C PROV models provenance around entities, activities, and responsible agents. Applicability: the mock JSON does not need the full ontology, but official observations should retain publisher, observation and retrieval dates, transformation notes, source URL, scope, unit, and limitations, while synthetic offers should retain generator and version information. Source: `https://www.w3.org/TR/prov-dm/`.
- NSI publishes quarterly housing-price indices for Sofia. The current Q1 2026 values with 2025 as the stated base are 109.14 overall, 108.24 for new dwellings, and 109.98 for existing dwellings; the data are preliminary and do not provide individual listings. Applicability: these are suitable real market-context observations, not valuation evidence for a mock offer. Source: `https://www.nsi.bg/statistical-data/98/328`.
- BNB's 27 July 2026 release reports June 2026 new-business housing-credit values of 2.41% average interest, 2.75% APR, and EUR 767.1 million volume. Applicability: these can seed a clearly dated mortgage reference card and sample assumption, but they do not replace a bank offer. - Eurostat provides free programmatic access to statistical datasets and publishes `prc_hpi_q` for quarterly house-price indices. Applicability: a bounded Bulgaria observation can demonstrate an API-shaped source export, with a stored snapshot because the prototype must run offline and Eurostat exposes the latest database rather than historical versions of the database itself. Source: `https://ec.europa.eu/eurostat/web/user-guides/data-browser/api-data-access/api-introduction`.
- Sofia's urban-data portal exposes SofiaPlan district and neighborhood GeoJSON resources, but the currently inspected district resource states that license rights are not specified. ### Edge Cases

- The prototype is opened from `file://` after extraction, where `fetch()` of sibling JSON and persistent storage may behave differently across browsers.
- `localStorage` may be disabled, blocked, cleared, or unavailable for an opaque origin; the session must remain usable with an in-memory fallback.
- JavaScript may be disabled or fail; navigation, requirements reading, source labels, and core sample content should remain understandable.
- The extracted folder may be nested, renamed, or located in a path containing spaces or Cyrillic characters; all internal references must remain relative and URL-safe.
- A user may open a subpage directly rather than entering through `index.html`; every page needs orientation and a route back to the landing page.
- Official source URLs may be unavailable after the snapshot or their latest values may change; local data must retain observation and retrieval dates and never depend on live availability.
- SofiaPlan geometry may be accessible while its reuse license remains unspecified; the mockup must not treat accessibility as legal approval.
- Synthetic offers may be mistaken for real opportunities if a warning is only on the landing page; offer-level and export-level labels are required.
- Official aggregate housing indices may be mistaken for neighborhood prices or individual valuations; scope and limitation fields must prevent that inference.
- Currency conversion can introduce mixed-era or mixed-basis values; one visible base currency and explicit observation units are required.
- Zero investment base, zero loan term, zero discount denominator, negative cash flow, invalid rates, missing values, multiple cash-flow sign changes, and mathematically undefined IRR must produce Bulgarian explanatory states rather than `NaN`, infinity, or zero.
- Optimistic, base, and pessimistic scenarios may reverse ranking; the interface must show changed assumptions and not hide the underlying values.
- Very wide tables must remain readable on phones through cards, controlled horizontal scrolling, or compact summaries without dropping source or risk information.
- Risk, confidence, freshness, and recommendation state must not rely on color alone.
- Modals, tabs, filters, and comparison controls must remain keyboard-operable with visible focus and predictable focus restoration.
- Reduced-motion users must not receive essential information only through animation.
- Print and browser “Save as PDF” output must not include interactive controls, clipped tables, hidden warnings, or unreadable dark backgrounds.
- CSV text beginning with `=`, `+`, `-`, or `@` can be interpreted as a spreadsheet formula; sample text fields must be safely bounded or escaped.
- The complete requirements source contains Markdown tables, inline code, formulas, links, and nested headings; the HTML representation must preserve semantic order and formula text without executing embedded content.
- An archive may omit dotfiles or external parent assets; every required runtime asset and README must live inside `workdir/investment_instrument/`.
- The existing focused test may represent prior assumptions rather than current decisions; answers must update both implementation scope and the test contract together.
- The active worktree is dirty; implementation must not overwrite unrelated public-site, context, or request artifacts.

## Decision Register

### Decision Points

#### Decision Point: Начален демонстрационен сценарий

- Tag: `ask`
- Applies to: Task 3, `workdir/investment_instrument/index.html`; the first screen can emphasize different stakeholder stories and materially changes the information hierarchy.
- Alternative `Табло на анализатора`: Open with tasks, ranked sample offers, market indicators, warnings, and a clear path into one analysis.
  - Trade-offs: Immediately demonstrates operational value and breadth, but introduces more concepts on the first screen.
  - Expected codebase impact: Dense landing dashboard, shared offer cards, indicator cards, warning summaries, and guided next-step controls.
- Alternative `Водена примерна сделка`: Open with one synthetic apartment and a step-by-step journey from offer through scenarios to human decision.
  - Trade-offs: Easier narrative and lower cognitive load, but provides less immediate evidence of portfolio comparison and weekly operations.
  - Expected codebase impact: Story-led hero, progress sequence, one featured offer, and stronger cross-page deep links.
- Alternative `Преглед за ръководител`: Open with business outcomes, source readiness, pipeline health, risk distribution, and recent approvals.
  - Trade-offs: Strong stakeholder overview, but underrepresents hands-on analyst workflows.
  - Expected codebase impact: Executive metrics, governance panels, and fewer offer details above the fold.
- Rationale/Resolution: The input asks for a vivid, self-explanatory demonstration but does not choose a primary audience or first-use narrative.

#### Decision Point: Обхват на страниците и навигацията

- Tag: `ask`
- Applies to: Task 3 route set; page count changes navigation complexity, story coverage, and maintenance cost.
