### Goal

Strengthen the homepage portfolio evidence by prominently presenting Елемаг, Бебелан, and ОББ Интерлийз as three equally weighted flagship projects within the Experience section, while preserving the complete existing project timeline.

### Stakeholders and user need

- Primary users: prospective property owners, investors, corporate clients, architects, and partners evaluating ATISTAT’s execution quality.
- Stakeholder: the client requesting stronger visual emphasis on representative completed work.
- User need: visitors should encounter convincing project evidence immediately within the Experience section instead of relying solely on the complete timeline.
- Business value: the selected projects establish the expected standard of execution and help attract clients seeking comparable quality.

### Scope

- Add a distinct flagship-project subsection to the Experience section.
- Place it immediately after the complete `at-opit__head` header and before the existing `at-home-timeline`.
- Add the subsection to all six Experience-page documents:
  - `index.html`
  - `index-bg.html`
  - `index-en.html`
  - `index.html?lang=bg.html`
  - `index.html?lang=en.html`
  - `opit/index.html`
- Use the localized subsection heading:
  - Bulgarian: `ЗНАКОВИ ПРОЕКТИ`
  - English: `FLAGSHIP PROJECTS`
- Present three equally prominent editorial cards in this order:
  1. Елемаг / Elemag
  2. Бебелан / Bebelan
  3. ОББ Интерлийз / UBB Interlease
- Give all three cards the same grid span, image treatment, information structure, and visual prominence.
- Display the following verified information on every card:
  - Project name
  - Year
  - Building type
  - Service
  - Experience attribution
  - Concise project-specific marketing paragraph
  - Localized “View gallery” action
- Use these verified project facts:
  - Елемаг: 2021; residential building; construction; experience with Engineering Systems.
  - Бебелан: 2025; office and warehouse building; fit-out works; experience with Engineering Systems.
  - ОББ Интерлийз: 2025; office building; construction; experience with Engineering Systems.
- Draft concise Bulgarian and English marketing descriptions using only verified workspace facts. Do not invent quantities, outcomes, client testimonials, awards, technical specifications, schedules, budgets, or performance claims.
- Select the strongest existing gallery photograph for each project based on composition, subject clarity, and suitability for a consistent wide crop.
- Create one appropriately sized, optimized local WebP flagship image per project. Do not load the existing full-resolution gallery originals directly in the normal page layout.
- Make each localized “View gallery” control open the existing reusable gallery dialog filtered to the corresponding project.
- Preserve the dialog’s existing close behavior and focus restoration.
- Keep the existing 13-milestone desktop timeline, responsive navigation, mobile cards, and project galleries available below the new subsection.
- Add or update automated tests covering the new subsection, localized parity, asset references, accessibility, responsive behavior, and gallery interaction.
- Keep canonical and version-suffixed shared CSS and JavaScript assets byte-identical.

### Layout and responsive behavior

- Use three equally sized cards in one row where the available desktop width supports them.
- Preserve equal prominence when the cards wrap at narrower widths.
- Stack cards into a readable single-column layout on small screens.
- Use a consistent image aspect ratio and crop treatment across all three cards.
- Prevent horizontal overflow from 320 CSS pixels upward.
- Keep text readable without truncating required project information.
- Ensure gallery controls meet the existing 44-by-44 CSS-pixel minimum target convention.
- Preserve useful content and gallery controls when JavaScript is unavailable, except for behavior that inherently requires the existing dialog script.

### Localization and accessibility

- Provide faithful Bulgarian and English headings, metadata labels, descriptions, action labels, image alternative text, and accessible names.
- Use semantic subsection and article/card markup with a valid heading hierarchy.
- Ensure every gallery action is keyboard operable and visibly focusable.
- Associate each card image and action with the correct project.
- Do not expose decorative content redundantly to assistive technology.
- Honor the existing reduced-motion behavior.

### Constraints

- Preserve the static, dependency-free architecture.
- Do not add third-party JavaScript libraries or a build pipeline.
- Reuse the existing design tokens, typography, gallery dialog, and interaction patterns.
- Prioritize the homepage hero as before; flagship images remain below the hero and must not compete with its loading priority.
- Use only local media assets.
