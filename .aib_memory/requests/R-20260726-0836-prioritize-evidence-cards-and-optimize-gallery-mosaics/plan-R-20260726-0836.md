## Goal

Make the selected Experience evidence card the primary visual element, retain compact chronological navigation on desktop and responsive layouts, and reduce normal-page mosaic payload while making every gallery launcher visibly interactive. The work affects six duplicated Experience documents, two shared stylesheet copies, two shared JavaScript copies, 28 new preview assets, static and browser regression coverage, and durable product context.

## Constraints

- Preserve the existing 13 milestones, chronological order, evidence-card content and dimensions, stacked responsive cards, gallery project membership, full-resolution dialog sources, dialog behavior, and focus restoration.
- Keep 860px as the desktop/responsive boundary: desktop behavior applies above 860px, and responsive behavior applies at 860px and below.
- Preserve the desktop rail’s approximately five-complete-marker viewport, free touch/trackpad panning, proximity snapping, edge fades, Previous/Next controls, active-marker centering, and automatic tab activation.
- Use a static 13-link responsive navigation region enhanced by JavaScript; the links must remain useful when JavaScript is unavailable.
- Move responsive marker focus with Left/Right Arrow keys without activating a destination; activate with Enter, Space, or click.
- After responsive activation, scroll to and focus the mapped card container; update persistent current-marker state only on explicit activation, not ordinary vertical scrolling.
- Store all 28 flat ASCII thumbnail files in `wp-content/uploads/2026/07/gallery-thumbnails/`.
- Keep each preview thumbnail in WebP format at exactly 160×160 pixels and no larger than 20KB; preserve full-resolution PNG/JPEG sources inside the dialog.
- Preserve `loading="lazy"` and `decoding="async"` on mosaic preview images where currently applicable.
- Use Bulgarian overlay text `Виж галерия` in `index.html`, `index-bg.html`, and `index.html?lang=bg.html`; use English overlay text `View gallery` in `index-en.html`, `index.html?lang=en.html`, and `opit/index.html`.
- Keep `wp-content/themes/atistat/assets/css/main.css` byte-identical to `wp-content/themes/atistat/assets/css/main.css?ver=1784544801.css`, and keep `wp-content/themes/atistat/assets/js/main.js` byte-identical to `wp-content/themes/atistat/assets/js/main.js?ver=1784544801`.
- Preserve correct root-relative asset paths in the five root documents and `../wp-content/...` paths in `opit/index.html`.
- Do not add third-party JavaScript, a package dependency, or a build pipeline.
- Do not optimize, remove, or replace the full-resolution dialog assets; do not redesign evidence cards, remove responsive cards, change project-detail content, or alter milestone chronology.

## Success criteria

- Each of the six Experience documents renders, above 860px, the selected evidence panel first, the localized instruction second, and the compact desktop stage third.
- The desktop rail still exposes all 13 milestones in the established order and interaction model, displays approximately five complete milestones, reduces milestone-image height by approximately 35–40%, uses 16–20px endpoint years, and uses 9–10px endpoint captions.
- At 860px and every smaller supported width, each document exposes 13 static responsive markers above the unchanged 13 stacked cards, with approximately three complete markers visible and without desktop endpoint blocks or separate Previous/Next controls.
- Responsive Left/Right Arrow keys move roving marker focus and center the marker without scrolling to a card; Enter, Space, and click navigate to and focus the mapped card container.
- Responsive activation honors reduced motion and persists the last explicitly activated marker as current even when the visitor later scrolls the cards directly.
- JavaScript failure leaves the responsive links and all 13 stacked cards available in source order.
- `wp-content/uploads/2026/07/gallery-thumbnails/` contains exactly 28 expected WebP files; every file is 160×160 pixels and at most 20KB.
- Every desktop and responsive mosaic uses only the shared thumbnail URLs, while every dialog retains its original full-resolution source set and order.
- Every mosaic remains one native button with its existing accessible name, a persistent non-intercepting gallery icon/text overlay, and visible hover and keyboard-focus feedback.
- The six documents preserve route parity, the `opit/index.html` prefix rule, all 13 milestones, all gallery mappings, and language-correct overlay copy.
- The two stylesheet copies and two JavaScript copies are byte-identical.
- The rendered page has no page-level horizontal overflow at 320px, responsive interaction passes at the 860px boundary, dialog opening/closing and invoker-focus restoration remain correct, and no first-party console errors are reported.
- `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_*.py' -v` completes with no failures or errors.
- `.aib_memory/context.md` passes its verification tool after the planned solution and residual-risk statements are applied.
